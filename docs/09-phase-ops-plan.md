# שלב 8: מוכנות תפעולית

> סטטוס: **בביצוע** (2026-10-16). סעיפים 1–2 הושלמו ואומתו.

## תוצאות אימות ה-Stack ב-Docker (סעיפים 1–2)

| בדיקה | תוצאה |
|---|---|
| בניית images (server, web, collector) | ✅ השרת רץ כ-`node`, read-only וללא dev deps; ה-collector רץ כמשתמש ייעודי |
| Least privilege | ✅ הטבלאות בבעלות `fs_owner`. ל-`fs_app` יש רק INSERT/SELECT על `audit_log`. ל-db ולשרת אין פורטים חשופים |
| Caddy + TLS | ✅ HTTP/2, אימות תעודה, כל כותרות האבטחה (CSP, HSTS, nosniff, Referrer, Permissions, COOP); ל-`sw.js` מוגדר `no-cache`. API ללא התחברות מחזיר 401 |
| ClamAV אמיתי | ✅ EICAR מזוהה (`Eicar-Test-Signature`). כשהסורק לא זמין מוחזרת שגיאה (fail-closed) |
| העלאה דרך ה-API | ✅ קובץ נקי: 201. קובץ שאינו תמונה: 415. **תמונה עם תוכן זדוני**: 422, נרשם Audit עם שם החתימה, התוכן נמחק (`content=NULL`) והתוכנית לא קושרה לקומה |
| Collector בקונטיינר מול הסימולטור | ✅ אש מגיעה לשרת. Ack וחזרה לשגרה עובדים. השרת הושבת: האירועים נשמרו ב-outbox (502 עם backoff) והגיעו לאחר החזרה. רכזת לא מגיבה וגם Collector שנעלם (watchdog) פותחים התרעת תקשורת שנסגרת אוטומטית |
| E2E בדפדפן דרך Caddy | ✅ 13/13 (פעמיים): secure context, עוגיית `__Host-` מסוג Secure/HttpOnly/Lax, RTL, axe, התרעה חיה ב-WebSocket תוך ~130ms, Ack, ביטול session ב-logout (עוגייה שנשמרה מחזירה 401), אין הפרות CSP |

**ממצאים שתוקנו:**
- **הפרת CSP (`script-src eval`) מ-Zod 4.** בזמן יצירת סכמות הספרייה בודקת אם `new Function` זמין. ה-CSP חסם את הבדיקה (תקין), אבל הדיווח על הפרה מסתיר הפרות אמיתיות. נוסף `apps/web/src/zod-csp.ts` עם `jitless`, והוא הייבוא הראשון בקליינט. בשרת אין CSP, ושם ה-JIT נשאר פעיל.
- **הערה על EICAR:** ב-ClamAV החתימה היא hash של הקובץ כולו (68 בתים), ולכן EICAR שמוטמע בתוך תמונה לא יזוהה. זו התנהגות תקינה של ClamAV ולא של המערכת. חתימות אמיתיות (ndb/ldb) מזוהות בכל מקום בקובץ. אימות המסלול המלא נעשה בחתימת בדיקה זמנית, שהוסרה בסיום.
