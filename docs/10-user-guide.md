## 1. תפקידים והרשאות

התפקידים מוגדרים ב-Microsoft Entra ID (App Roles), והמערכת מקבלת אותם בכל התחברות.

| תפקיד | מה רואים | מה אפשר לעשות |
|---|---|---|
| **צופה** (Viewer) | אירועים, היסטוריה ומפות במבנים שהוקצו לו | צפייה בלבד |
| **מפעיל מוקד** (Operator) | כמו צופה | אישור קבלה (Ack), הערות וסימון צעדי נוהל |
| **ממונה בטיחות** (SafetyOfficer) | כמו מפעיל, ובנוסף דוחות | כמו מפעיל. מקבל התראות על המבנים שלו |
| **מנהל מערכת** (FireAdmin) | **כל המבנים** | ניהול מלא: מבנים, Collectors, נקודות, מפות, משתמשים, נהלים, הגדרות התראות ויומן פעולות |

- את המבנים של כל משתמש (לכל התפקידים מלבד מנהל) קובעים במסך **משתמשים והרשאות**.
- משתמש שלא שויך למבנה לא רואה אירועים. זו התנהגות מכוונת.
- ההרשאות נאכפות בשרת. הסתרה של כפתורים בממשק היא נוחות בלבד ואינה מנגנון ההגנה.

## 2. התחברות

- כניסה בכפתור **"התחברות עם Microsoft"**, עם חשבון המוסד (כולל MFA לפי מדיניות המוסד).
- החיבור מתנתק אחרי 60 דקות ללא פעילות, ובכל מקרה אחרי 12 שעות (ברירות מחדל).
- **הודעות שגיאה נפוצות:**
  - "לחשבון שלך לא הוקצה תפקיד": יש לפנות למנהל המערכת או ל-IT כדי לקבל App Role.
  - "החשבון אינו פעיל": החשבון הושבת במערכת.
- אם התחברות Microsoft אינה זמינה בזמן אירוע: ראו [כניסת חירום](#10-כניסת-חירום-break-glass), אם הוגדרה במוסד.

## 3. מסך האירועים הפעילים

המסך הראשי. הוא מתעדכן **בזמן אמת**, בלי לרענן את הדף.

- **אריחי סיכום** לפי קטגוריה. המספר הגדול הוא כמות האירועים הפעילים. "X לא אושרו" מציין אירועים שעדיין לא קיבלו אישור קבלה.
- **סדר הטבלה:** קודם אירועים שלא אושרו, אחר כך לפי חומרה, ובכל דרגה החדשים קודם.

| קטגוריה | משמעות |
|---|---|
| **אש** | אזעקת אש ברכזת. החומרה הגבוהה ביותר |
| **קדם-אזעקה** | התראה מוקדמת של גלאי |
| **תקלה** | תקלה בגלאי, בקו או בציוד |
| **פיקוח** | מצב פיקוח (Supervisory) |
| **מנוטרל** | נקודה שנוטרלה ברכזת (Out of service / Disabled) |
| **בדיקה** | מצב בדיקה |
| **תקשורת** | רכזת שאינה מגיבה, או Collector שנעלם (באנר אדום בראש המסך) |

**אש וקדם-אזעקה שחזרו לשגרה בלי שאושרו נשארים ברשימה.** הם מסומנים "חזר לשגרה ברכזת. ממתין לאישור", והצליל ממשיך עד אישור הקבלה. כך אירוע שהופיע והסתיים בלי שמישהו ראה אותו לא נעלם מהמסך. אם באותה נקודה נפתח אירוע חדש, מוצג רק העדכני. תקלות ואירועי תקשורת יוצאים מהרשימה כשהם מסתיימים, וכל האירועים נשמרים בהיסטוריה.

- **התראה קולית:** הכפתור "הפעלת התראה קולית" מפעיל צליל כל עוד יש אירוע אש שלא אושר. בגלל מדיניות הדפדפנים יש ללחוץ עליו פעם אחת אחרי כל טעינה של הדף.
- **באנר אדום בראש המסך** ("רכזות אינן מגיבות" או "Collectors"): הניטור חלקי. **יש לעבור מיד לרכזת או למוקד הרגיל** ולדווח ל-IT.
- **נגישות:** כל המסך נגיש למקלדת. אירוע אש חדש מוכרז גם לקורא מסך.

## 4. טיפול באירוע

1. לוחצים על שם הנקודה כדי לפתוח את דף האירוע: פרטים, מיקום, קישור למפה, הערות ונוהל.
2. **אישור קבלה** (Ack) מסמן שראיתם את האירוע ואתם מטפלים בו. אפשר להוסיף הערה (למשל "מאבטח נשלח").
   - האישור עוצר את הצליל ואת ההסלמה.
   - האישור **לא** משנה דבר ברכזת. המערכת קוראת בלבד.
3. **נוהל:** אם הוגדר נוהל לקטגוריה או למבנה, מוצג צ'קליסט. כל סימון נרשם עם שם ושעה, וכל המחוברים רואים אותו מיד.
4. **הערות:** אפשר להוסיף הערות גם אחרי האישור. הן נשמרות בהיסטוריה.

## 5. מבנים, קומות ומפות

- **מבנים** מציג את רשימת המבנים בהרשאה, ובכל מבנה את הקומות.
- **מפת קומה** מציגה את הנקודות על תוכנית הקומה, בצבע לפי המצב הנוכחי. מתחת למפה יש **טבלת נקודות** עם המצב, המיקום וקישור לאירוע. זו החלופה הנגישה למפה (מקלדת וקורא מסך).
- מדף אירוע, "הצגה במפה" פותח את הקומה עם הנקודה מודגשת.

## 6. ההתראות שלי

במסך **ההתראות שלי** (בפינה העליונה):

- **ערוצים:** בוחרים מאילו ערוצים לקבל התראות (Push, דוא"ל, SMS, WhatsApp), מתוך הערוצים שהמנהל הפעיל.
- **טלפון:** מזינים מספר ומאמתים אותו בקוד שנשלח ב-SMS או ב-WhatsApp (תקף ל-10 דקות). המספר נשמר מוצפן.
- **WhatsApp** נשלח רק אחרי הסכמה מפורשת בתיבת הסימון.
- **Push בדפדפן או בטלפון:** לוחצים "הפעלת התראות במכשיר זה" ומאשרים את בקשת הדפדפן. צריך לחזור על זה בכל מכשיר.
- **בדיקה עצמית:** "שליחת התראת בדיקה אליי" שולחת הודעת ניסיון לכל הערוצים שלך ומציגה את התוצאה בכל ערוץ.
- **מי מקבל התראות:** ממוני בטיחות (במבנים שלהם) ומנהלי מערכת. אירועי תקשורת נשלחים למנהלים בלבד. אירועים קרובים בזמן מקובצים להודעה אחת. **אש שלא אושרה תוך 3 דקות (ברירת מחדל) מוסלמת** לערוצים נוספים.

## 7. דוחות

לממונה בטיחות (במבנים שלו) ולמנהל:
- **אירועים:** לפי טווח תאריכים, מבנה וקטגוריה, עם ייצוא ל-CSV שנפתח באקסל כולל עברית.
- **זמני תגובה:** חציון וממוצע של הזמן עד אישור, לפי קטגוריה.
- **נקודות מנוטרלות ותקלות פתוחות:** מה מנוטרל או תקול כרגע, ומאז מתי.
- **הדפסה:** הדפסה ישירה מהדפדפן נותנת תצוגה נקייה.

## 8. ניהול המערכת

למנהל מערכת בלבד. כל פעולה נרשמת ב**יומן פעולות**.

| מסך | מה עושים |
|---|---|
| **ניהול מבנים** | פקולטות, מבנים וקוד מבנה (משמש בייבוא CSV) |
| **Collectors** | רישום Collector חדש. **המפתח (Token) מוצג פעם אחת בלבד**, ויש להעביר אותו בצורה מאובטחת לקובץ ה-env של ה-Collector. אפשר להחליף מפתח או להשבית Collector |
| **רכזות ונקודות** | שיוך רכזת למבנה, שם תצוגה ומיקום לכל נקודה. **ייבוא CSV**: הכול או כלום, ושגיאות מוצגות לפי שורה. כותרות נתמכות: `device_instance`, `object_type`, `object_instance`, `building_code`, `floor_level`, `label`, `location`, `x`, `y` (או בעברית: רכזת, סוג אובייקט, מספר אובייקט, קוד מבנה, קומה, שם, מיקום) |
| **קומות ומפות** | יצירת קומה והעלאת תוכנית (PNG, JPEG או WebP, עד 10MB). הקובץ נסרק באנטי-וירוס, וקובץ חשוד נחסם ונמחק. **שיבוץ:** בוחרים נקודה מהרשימה, ואז לוחצים על המפה או מזינים X ו-Y באחוזים. בסוף לוחצים "שמירת מיקום" |
| **משתמשים והרשאות** | שיוך מבנים, השבתה והפעלה. השבתה מנתקת את המשתמש מיד. "חשבון חירום" מסומן בתג אדום |
| **נהלים** | צ'קליסט לפי קטגוריה. נוהל של מבנה מסוים גובר על הנוהל הכללי. עריכה לא משנה ביצועים שכבר התחילו |
| **הגדרות התראות** | הפעלת ערוצים, פרטי ספקים (הסודות נשמרים מוצפנים ולא מוצגים שוב), מדיניות לכל קטגוריה, הסלמה וקיבוץ. "שליחת בדיקה" שולחת הודעת ניסיון לכל ערוץ |
| **יומן משלוחים** | כל הודעה שנשלחה, דולגה או נכשלה, והסיבה. הנמענים מוסווים |
| **יומן פעולות** | Audit של התחברויות, שינויים, העלאות וכניסות חירום. אי אפשר למחוק או לערוך אותו מהמערכת |

## 9. תפעול שוטף (IT)

### התקנה ראשונה
```bash
deploy/install.sh                       # בודק דרישות ויוצר .env (600) עם סודות אקראיים. לא דורס קובץ קיים
# להעתיק את תעודת ה-TLS של המוסד ל-deploy/local/certs/{cert,key}.pem
docker compose -f deploy/docker-compose.yml --env-file .env build
docker compose -f deploy/docker-compose.yml --env-file .env up -d
curl -fsS https://<host>/healthz
```
מיד אחרי ההתקנה **מגבים את `.env`** בכספת הסודות של המוסד, בנפרד מגיבויי ה-DB.

### עדכון גרסה
```bash
git pull
docker compose -f deploy/docker-compose.yml --env-file .env build
docker compose -f deploy/docker-compose.yml --env-file .env up -d   # המיגרציות רצות אוטומטית בעלייה
```
לפני עדכון: גיבוי. אחרי עדכון: `healthz`, התחברות, וראייה שה-Collectors מחוברים.

### גיבוי ושחזור
- גיבוי יומי מוצפן (cron): `deploy/backup/backup.sh` (פירוט ב-README).
- **בדיקת שחזור חודשית** ל-DB זמני: `deploy/backup/restore.sh`.
- כדי לקרוא גיבויים ישנים צריך את `SETTINGS_ENCRYPTION_KEY` שהיה בתוקף בזמן הגיבוי. שומרים אותו כל עוד הגיבויים שמורים.

### בדיקות תקופתיות
| תדירות | בדיקה |
|---|---|
| יומית | אין באנר אדום. ב-**Collectors** כולם "מחובר" |
| שבועית | "שליחת בדיקה" ב**הגדרות התראות** לכל ערוץ. סקירת **יומן משלוחים** לכשלים |
| חודשית | שחזור גיבוי. סקירת **יומן פעולות**. עדכוני מערכת הפעלה ו-images |
| רבעונית | תרגיל מול הרכזת (נקודת בדיקה) מקצה לקצה. בדיקת כניסת חירום ואחריה `reset` |

### Collector
מותקן על מחשב קטן ברשת הרכזות (ראו README, "Collector"). הוא קורא בלבד ושולח ב-HTTPS יוצא בלבד. כשהשרת לא זמין, האירועים נשמרים אצלו ונשלחים כשהחיבור חוזר.

## 10. כניסת חירום (Break-glass)

**מטרה:** גישה למסך הניטור כשהתחברות Microsoft אינה זמינה. **כבוי כברירת מחדל.** מפעילים רק אחרי אישור ה-IT וקביעת נוהל.

### הקמה (IT, מסוף השרת)
```bash
# ב-.env: BREAK_GLASS_ENABLED=true, ו-BREAK_GLASS_ALLOWED_CIDRS=<רשת חדר הבקרה>; ואז up -d
docker compose -f deploy/docker-compose.yml --env-file .env exec server node apps/server/dist/cli/break-glass.js create bg-ops --name "חירום מוקד"
```
- הסיסמה וסוד ה-TOTP **מוצגים פעם אחת**.
- את הסוד מזינים באפליקציית אימות (Microsoft Authenticator, Google Authenticator וכו') על **מכשיר ייעודי** שנשמר בחדר הבקרה. בוחרים "הזנה ידנית", SHA1, 6 ספרות, 30 שניות.
- את הסיסמה מדפיסים ושומרים ב**מעטפה חתומה בכספת**. אין לשמור אותה בדוא"ל, בצ'אט או בכרטיס תקלה.
- **חובה להגדיר לפחות ערוץ התראה אחד למנהלים** (סעיף 8). כל כניסת חירום שולחת להם התראה מיידית.

### שימוש בזמן תקלה
1. במסך ההתחברות פותחים **"כניסת חירום"**.
2. מזינים שם משתמש, סיסמה וקוד בן 6 ספרות מהאפליקציה.
3. מופיע **באנר אדום קבוע**. החיבור מוגבל לשעתיים, וכל פעולה מתועדת.
4. אם ההודעה היא "פרטי הכניסה שגויים, או שהחשבון ננעל זמנית": אחרי 5 ניסיונות כושלים החשבון ננעל ל-15 דקות.

### אחרי השימוש (חובה)
```bash
docker compose ... exec server node apps/server/dist/cli/break-glass.js reset bg-ops   # פרטים חדשים, ניתוק sessions
```
פקודות נוספות: `list`, `disable <user>`, `enable <user>`, `scope-all <user>` (מוסיפה למפעיל את כל המבנים, למשל אחרי הוספת מבנה).

## 11. החלפת מפתח ההצפנה

`SETTINGS_ENCRYPTION_KEY` מצפין את סודות הספקים, את מספרי הטלפון ואת סודות ה-TOTP. מחליפים אותו אם יש חשש לדליפה, או לפי מדיניות. **התהליך לא מפסיק את השירות:**

```bash
D="docker compose -f deploy/docker-compose.yml --env-file .env"
cp .env .env.backup-$(date +%F)                         # 1. גיבוי
$D exec server node apps/server/dist/cli/rotate-key.js generate   # מפתח חדש
# 2. ב-.env:  SETTINGS_ENCRYPTION_KEY=<חדש>  ו-SETTINGS_ENCRYPTION_KEY_PREVIOUS=<ישן>
$D up -d server
$D exec server node apps/server/dist/cli/rotate-key.js --dry-run   # 3. בדיקה: אין "undecryptable"
$D exec server node apps/server/dist/cli/rotate-key.js             #    הצפנה מחדש בטרנזקציה אחת
# 4. מוחקים את SETTINGS_ENCRYPTION_KEY_PREVIOUS מ-.env
$D up -d server
```
- אם המפתח הישן חסר, הפקודה **נעצרת בלי לשנות דבר**.
- הרצה חוזרת אינה מזיקה.
- את המפתח הישן שומרים בכספת כל עוד שמורים גיבויים מלפני ההחלפה.

## 12. פתרון תקלות

| תסמין | בדיקה ופתרון |
|---|---|
| באנר "Collectors" | ה-Collector לא שלח נתונים: מחשב כבוי, רשת או חומת אש. על ה-Collector: `docker compose logs collector`. הודעות `server responded 502` או `connection refused` מצביעות על בעיה בדרך לשרת. האירועים נשמרים ויישלחו |
