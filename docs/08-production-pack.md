## 1. מודל איומים (מעודכן לשלבים 1–5)

| נכס | איום | בקרות קיימות | סיכון שנותר |
|---|---|---|---|
| **רכזות האש** | שליחת פקודות / שינוי מצב | ה-Collector לקריאה בלבד: אין בקוד שירותי כתיבה, ובדיקה אוטומטית אוכפת זאת. ה-Collector ב-VLAN נפרד. השרת לא מתקשר עם הרכזות | נמוך. תלוי בהפרדת הרשת בשטח |
| **אמינות הניטור** | השתקה שקטה (רכזת, Collector, שרת או רשת נופלים) | Heartbeat, Watchdog, באנר אדום לכל המשתמשים, התראת תקשורת למנהלים, Outbox ב-Collector ובשרת | בינוני. **המערכת משלימה בלבד**, וזה מוצג בכל מסך |
| **חשבונות** | גניבת זהות, Brute force | Entra ID + MFA (Conditional Access), Session מגובב בשרת, Idle 60 דק', Absolute 12 שעות, rate limit, `__Host-` cookies | נמוך. תלוי במדיניות Entra של המוסד |
| **הפרדת מבנים** | IDOR / BOLA | scope נאכף ב-SQL בכל קריאה (התראות, קומות, קבצים, נהלים, דוחות, WebSocket). 404 זהה ל"לא קיים". בדיקות אוטומטיות | נמוך |
| **CSRF / Clickjacking** | פעולה מאתר זר | SameSite=Lax + בדיקת Origin בכל בקשה משנה, CSP `frame-ancestors 'none'` | נמוך |
| **Collector token** | גניבה ← הזרקת אירועי שווא או "ניקוי" אירועים | Token לכל Collector, נשמר כ-SHA-256, החלפה והשבתה מהממשק, rate limit, Audit לכשלי אימות | בינוני. **חובה לשמור את קובץ ה-env של ה-Collector עם הרשאות 600 ובמכונה מוקשחת**. אפשרות לשכבת mTLS ב-Caddy |
| **העלאת קבצים** | נוזקה, Polyglot, XSS | Allowlist לפי magic bytes, 10MB, ClamAV (fail-closed), הסגר, הגשה עם nosniff ו-CSP sandbox, ללא SVG/PDF | נמוך |
| **סודות ספקים / טלפונים** | דליפה מה-DB או מגיבוי | AES-256-GCM, המפתח בסביבה (לא ב-DB). Write-only בממשק. מוסווה ביומנים | בינוני. **ניהול המפתח** (ראו סעיף 4) |
| **התראות** | שליחה לנמען שגוי, הצפה | סינון לפי scope, קיבוץ, opt-in ל-WhatsApp, יומן משלוחים מוסווה | נמוך |
| **SSRF** | שרת מנוצל לפנייה לכתובות פנימיות | Push רק לשירותים מוכרים (allowlist), ספק SMS ב-https בלבד (מנהל בלבד), `redirect: error` | נמוך |
| **Audit** | מחיקת עקבות | טריגר append-only + תפקיד DB שאין לו UPDATE/DELETE/TRUNCATE (נבדק בפועל) | נמוך |

## 4. ניהול מפתחות וסודות

| סוד | איפה | גיבוי | החלפה |
|---|---|---|---|
| `SETTINGS_ENCRYPTION_KEY` | Secret manager או קובץ env בהרשאות 600 | **חובה, בנפרד מגיבוי ה-DB** | כרגע ידנית: החלפת המפתח מחייבת להזין מחדש את סודות הספקים ואת מספרי הטלפון. Re-encryption אוטומטי: שיפור עתידי |

| `OIDC_CLIENT_SECRET` | כנ"ל | — | לפי מדיניות Entra (רצוי Certificate) |
| סיסמאות DB (`fs_owner`, `fs_app`) | כנ"ל | — | `ALTER ROLE … PASSWORD` |
| Collector tokens | אצל ה-Collector בלבד (בשרת: hash) | — | כפתור "החלפת מפתח" |
| Passphrase לגיבוי | Secret manager, **לא ליד הגיבויים** | חובה | גיבוי חדש עם passphrase חדש |

## 5. Checklist לעלייה לייצור

### תשתית ופריסה
- [ ] שרת/VM ייעודי, מעודכן, עם חומת אש: נכנס 443 בלבד; יוצא רק לספקים, Entra, Push, מראות ClamAV (דרך Proxy אם נדרש).
- [ ] Collector על מכונה נפרדת ב-VLAN של הרכזות. יוצא: UDP 47808 לרכזות, 443 לשרת בלבד.
- [ ] תעודת TLS מה-CA של המוסד (`deploy/local/certs`), ובדיקה ב-SSL Labs או בכלי פנימי.
- [ ] `deploy/sql/least-privilege.sql`, ואחריו `MIGRATION_DATABASE_URL` (owner) ו-`DATABASE_URL` (app). ✔ נבדק: לתפקיד ה-app אין UPDATE/DELETE/TRUNCATE על audit_log.
- [ ] `SETTINGS_ENCRYPTION_KEY`, `AUDIT_IP_PEPPER` ו-`OIDC_*` ב-secret store. `.env` בהרשאות 600.
- [ ] גיבוי יומי: `deploy/backup/backup.sh` ב-cron, העתקה off-host, **ובדיקת שחזור חודשית** עם `restore.sh` לבסיס בדיקה. ✔ נבדק: הצפנה, שחזור, זיהוי passphrase שגוי, זיהוי קובץ ששונה.
- [ ] ניטור חיצוני (Uptime) ל-`/healthz` ולבאנר "degraded" (`/api/system/status`).
- [ ] ClamAV: בדיקת EICAR בפועל ועדכון חתימות.

### אימות והרשאות
- [ ] App Registration, App Roles, הקצאה לקבוצות, "Assignment required", ו-Conditional Access עם MFA.
- [ ] בדיקה שמשתמש בלי תפקיד נחסם, ושממונה רואה רק את המבנים שלו (גם בדוחות, במפות, בקבצים וב-WebSocket).
- [ ] חשבון חירום (break-glass): **עדיין לא מומש**. כרגע ההחלטה היא להסתמך על Entra. ⚖️ לבחינה מול ה-IT.

### פונקציונליות ואמינות
- [ ] חיבור לרכזת Siemens אמיתית (קריאה בלבד), ואימות מיפוי הקטגוריות מול ה-PICS / Object list.
- [ ] תרגיל: ניתוק רכזת, ניתוק Collector ונפילת שרת. מוודאים באנר, התראה וחזרה.
- [ ] שליחת בדיקה בכל ערוץ מההגדרות. ממונה מאשר קבלה ב-SMS, WhatsApp, דוא"ל ו-Push.
- [ ] תרגיל הסלמה: אש בלי Ack, הסלמה למנהלים.

### אבטחה
- [ ] `npm audit --omit=dev` ו-`pip-audit` לפני כל פריסה. SBOM (CycloneDX) מה-CI.
- [ ] **בדיקת חדירות** חיצונית ⚖️: Web, API, WebSocket, Ingest, העלאת קבצים, Collector, Docker.
- [ ] סקירת יומן ה-Audit (התחברויות, כשלי הרשאה, ingest.auth, file.upload).

### פרטיות ⚖️
- [ ] ממונה הגנת הפרטיות: מפת המידע (סעיף 2), רישום מאגר אם נדרש, זמני שמירה, תיקון 13.
- [ ] DPA מול ספק ה-SMS ו-Meta, ובחינת העברת מידע מחוץ לישראל.
- [ ] אישור טיוטות: מדיניות פרטיות, מדיניות עוגיות ותנאי שימוש (בממשק).

### נגישות ⚖️
- [ ] ✔ axe (WCAG 2.1 AA) על כל המסכים, בהיר וכהה. נבדקו גם מקלדת, זום ו-RTL.
- [ ] בדיקה ידנית עם NVDA / VoiceOver, ובמובייל (iOS ו-Android).
- [ ] יועץ נגישות (ת"י 5568), השלמת פרטי הרכז בהצהרת הנגישות ותאריך.

## 6. פיילוט (שלב 6)

1. **היקף:** מבנה אחד, רכזת אחת (או Access Point), 2–3 ממוני בטיחות ומפעיל מוקד אחד. **במקביל** למוקד ולנהלים הקיימים, בלי לשנות אותם.
2. **הכנה:**
   - הקבלן מפעיל BACnet ורישיון, ומוסיף את ה-Collector כנמען התראות (אופציונלי).
   - Object list / EDE ← ייבוא CSV של שיוך הנקודות.
   - תוכנית קומה ← שיבוץ.
3. **4 שבועות של מדידה:**
   - כל אירוע ברכזת מופיע במערכת. משווים מול יומן הרכזת: **יעד 100%**.
   - השהיה מרכזת למסך (יעד פחות מ-3 שניות), ולהודעה (יעד פחות מ-10 שניות).
   - אפס התראות שווא שמקורן במערכת. זמינות Collector ושרת.
   - משוב משתמשים על המסכים, ההודעות והנהלים.
4. **תרגילים:** אש מבוימת או מצב בדיקה בתיאום הקבלן, ניתוק רשת, Restart לשרת ול-Collector.
5. **קריטריון יציאה:** יעדי שלב 3 הושגו, אין ממצאי אבטחה פתוחים בחומרה גבוהה, והגורמים בסעיף 7 אישרו.
